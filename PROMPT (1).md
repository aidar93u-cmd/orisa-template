## 2. ЖЁСТКИЕ ПРАВИЛА (на всех этапах)

1. **Названия.** В админке (label, instructions, названия групп и блоков) только по-русски и понятно редактору. Слаги, `name`, `key`, папки, файлы, функции только по-английски. Пример: label «Первый экран», name `hero`; label «Заголовок», name `title`; к полям, где это неочевидно, добавляй `instructions`.
2. **Один блок = одна папка.** Внутри ровно `template.php` (вёрстка) и `fields.php` (ACF). На этапе 6 добавится `demo.php`. Больше ничего.
3. **Разметка 1:1.** Классы-обёртки, `data-*`, порядок вложенности сохраняй дословно: `main.js` и плагины инициализируются по ним. В HTML заменяются только текст, ссылки и пути (на PHP-вывод). Структуру не «улучшай», новых классов не вводи (исключение: `wp-fixes.css`). Любой класс, который блок может вывести, должен существовать в исходной вёрстке.
4. **Не объединяй блоки «из экономии».** Блоки сливаются в один (с полем `variant`), только если разметка отличается лишь модификаторами классов. Если структура разная, это разные блоки. Верность вёрстке важнее числа блоков. Любое объединение и неочевидное решение записывай в `docs/DECISIONS.md` одной строкой с причиной.
5. **Всё контентное в ACF**: видимые тексты, ссылки (поле Link), картинки (поле Image, возврат ID), видео-ссылки (YouTube и т.п.), телефон/почта/адрес. Чисто декоративная графика (фоны, SVG-фигуры, иконки интерфейса) остаётся в теме. Список этих исключений положи в `docs/DECISIONS.md`, чтобы заказчик мог их пересмотреть.
6. **Безопасность.** Весь вывод экранируется: `esc_html`, `esc_attr`, `esc_url`; WYSIWYG через `wp_kses_post`. Каждый PHP-файл начинается с `defined('ABSPATH') || exit;`. `$_GET/$_POST` только санитизированные.
7. **Пустые поля не ломают вёрстку.** Если поле пусто, его тег не выводится (кроме обёрток, на которых держится JS). Для этого сделай хелперы в `inc/helpers.php`: вывод Link-поля, картинки по ID (`wp_get_attachment_image` с нужным size и атрибутами), безопасный вывод текста.
8. **Оригинальные CSS/JS не правь вручную**, кроме этапа 1 (механическая чистка, см. там). Конфликты с WP решай отдельным `assets/css/wp-fixes.css`.
9. **Не выдумывай.** Не уверен (селектор, назначение файла, структура секции): проверь по коду. Если проверить нельзя, запиши в `docs/QUESTIONS.md`, иди дальше с самым безопасным вариантом.
10. **Git.** Если репозитория нет, сделай `git init` и первый коммит «baseline» **до любых правок**. Дальше один коммит на этап (на этапе 4 каждые ~5 блоков). Перед этапом убедись, что рабочее дерево чистое.
11. **Запрещено:** `register_block_type`, `block.json`, скиллы `wp-block-development`/`wp-block-themes` (это Gutenberg). Классический `page.php` + Flexible Content.
12. **Не пиши «работает», если не запускал.** Пиши «проверено статически» или «проверено в рантайме».
13. **После каждого этапа остановись**, дай краткий отчёт (раздел 6) и **жди моего «ок»**.

**Инструменты, если доступны:** `context7` (актуальные доки ACF/WP: проверяй сигнатуры, не пиши по памяти), `wordpress-router`/`wp-project-triage`, `wp-phpstan`, `security-and-hardening`, `verification-before-completion`. **Скриншоты и браузерную автоматизацию (Playwright и т.п.) не используй: проверка только статическая, финальную визуальную проверку делает заказчик вручную.**

### Как это работает

- **Загрузчик** `inc/acf-loader.php` на `acf/init` сканирует `blocks/*/fields.php`. Каждый файл **возвращает массив одного layout**: `key` (`layout_orisa_{slug}`), `name` (= имя папки), `label` (по-русски), `display => 'block'`, `sub_fields`. Загрузчик собирает их в одну группу «Секции страницы» с полем Flexible Content `page_sections` (Location: Post Type = page) и регистрирует через `acf_add_local_field_group`. Ключи полей `field_orisa_{slug}_{field}`.
- **Общая вкладка «Настройки блока»** загрузчик добавляет в каждый layout сам: `enabled` («Показывать блок», по умолчанию вкл) и `anchor` («Якорь (id)»). В `fields.php` блоков их не дублируй.
- **Вывод** (`page.php`/`front-page.php`): `if (have_rows('page_sections'))` → `while (have_rows(...))` → `the_row()` → `get_row_layout()` → пропуск, если `enabled` выключен → `get_template_part('blocks/' . $layout . '/template')`. Внутри блока: `get_sub_field()` и вложенные `while (have_rows('items'))`. Цикл выставляет флаги для условных скриптов (`matter`, `pricing-3` и т.д.). Нет секций: заглушка только для залогиненных редакторов.
- **«Настройки страницы»** (`inc/acf-page-settings.php`, для post type `page`, сайдбар/«side»): `header_style` (по умолчанию / светлое / прозрачное; варианты определи по оригиналу), `footer_style` (список вариантов подвала из оригинала: стандартный, `footer-7`, `-9`, `-13`, `-14`), `hide_header`, `hide_footer`, `body_class` (опционально). Нужны для разных главных и для `coming-soon`/`404`. `header.php`/`footer.php` читают их и подставляют вариант.
- **Options Page:** top-level «Настройки сайта» + подстраницы из `inc/options/*`. Читай через `get_field('…', 'option')`.
- **Копирайт:** в оригинале год подставляет JS (`main.js` гл.9). В поле хранится текст с токеном `{year}`, PHP заменяет его на `gmdate('Y')`.
- **Отключение Gutenberg:** `use_block_editor_for_post_type` → false для всех типов (записи на классическом редакторе), у `page` убрать `editor`, `wp_dequeue_style('wp-block-library')`, `wp-block-library-theme`, `global-styles`, `classic-theme-styles`.
